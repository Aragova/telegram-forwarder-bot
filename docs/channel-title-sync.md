# Синхронизация названий каналов и чатов с темами

## Причина
Rich-кнопки источника и получателя читают `Rule.source_title` и `Rule.target_title`, а `get_all_rules` / `get_rules_for_tenant` получают эти поля через `LEFT JOIN channels`. Существующие названия записываются при первом добавлении канала. Когда канал переименовали в Telegram, сохранённый `channels.title` оставался прежним.

## Решение
- При каждом запуске UI-бота (`--role bot` или `--role all`) сразу запускается **фоновый первый проход** синхронизации без ожидания шестичасового интервала.
- Следующий проход выполняется через 6 часов после завершения предыдущего.
- Используется список сохранённых активных каналов и групп, включая группы, добавленные только через конкретные темы (`thread_id IS NOT NULL`). Повторные ID источника/получателя проверяются только один раз за проход.
- Получаем актуальное имя через `bot.get_chat(channel_id)`; если бот не имеет доступа к приватному источнику, пробуем существующую авторизованную Telethon-сессию. Новые сессии не создаются.
- Для каждого найденного имени `refresh_channel_title` выполняет `UPDATE channels.title ... WHERE title IS DISTINCT FROM ...` для всех записей с тем же `channel_id`, включая темы этого чата; записываются только реальные изменения. Если группа переименована, название обновится во всех её темах и ролях источника/получателя.
- `channels.title` хранит название группы, даже когда запись относится к её теме. Название самой темы отдельно не хранится и не синхронизируется: интерфейс продолжает показывать её стабильный ID `(тема N)`. Этот PR исправляет именно переименования групп с темами, не меняя идентификаторы и маршрутизацию.
- Если Telegram недоступен или не вернул название, оставляем последнее сохранённое имя.
- Бот начинает обслуживать пользователей одновременно с первым проходом; обычно новые имена появляются в следующем открытом/обновлённом списке после завершения прохода. Уже отправленное Telegram-сообщение с кнопками автоматически не переписывается.

## Стабильность
- Лимит 3 одновременных запроса, таймаут 12 секунд на обращение к Telegram, без повторных запросов при rate limit в рамках прохода.
- Синхронизация работает только в UI- или legacy all-роли, не создаётся второй раз в worker и scheduler.
- Фоновая задача корректно отменяется при остановке приложения до закрытия Telegram-сессий.
- Таблица `routing`, логические позиции очереди, `posts`, `deliveries`, подписки, публикации и расписания не меняются.
- Формат Rich-кнопок из PR #516 оставлен без изменений; они автоматически используют новые названия из таблицы channels.

## Проверка после выкладки
1. Выполнить стандартный деплой ViMi Autoposting с перезапуском `forwarder_bot.service`.
2. Проверить журнал по маркеру `CHANNEL_TITLE_SYNC` и наличие итоговой строки `проверено/изменено/недоступно`.
3. Открыть `🔄 Правила → Список правил`, убедиться, что переименованные источник и получатель показываются на Rich-кнопках, включая «Тайная комната 2 (тема 12422)» → «Тайная 2 (тема 12422)».
4. Проверить приватный источник с действующей Telethon-сессией и группу, добавленную только через тему (без записи с `thread_id IS NULL`).
5. Если Telegram не имеет доступа к каналу, последнее сохранённое имя остаётся прежним.

Сервис `tg-bot-api.service` отдельно обновлять не требуется: используется уже настроенный Bot API, а при необходимости существующий Telethon-клиент.
