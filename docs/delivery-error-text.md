# Ошибки доставки: русские объяснения

Инцидент правила №208 (27.11.2026): после полного пересканирования и выбора позиции 29 старая попытка была архивирована, новый альбом из 10 сообщений получил статус sent, новая попытка verified; ошибок в очереди не осталось. Поэтому отдельное восстановление старых записей не требуется.

Для известных конфликтов состава очереди оператору показывается безопасная инструкция: выключить правило, проверить уже опубликованные сообщения в получателе, выполнить штатное «Пересканировать» → «Начать заново» и дождаться завершения. Не включая правило, выбрать нужный пост через «Начать с этого», затем включить правило. Иначе активное правило может начать публикацию сразу после пересканирования. Новый цикл допускает повторную публикацию ранее отправленных сообщений; не выбирать их без необходимости.

Неопределённый результат отправки — иной случай: сначала ручная сверка с Telegram, а не безусловное пересканирование.

`app/delivery_error_text.py` — единая таблица пользовательских причин и действий для проблемных доставок, журналов правила/системы и диагностики доставки. Сырые коды в PostgreSQL и технических логах сохраняются. Неизвестные ошибки получают честное русское описание без технических подробностей; при необходимости оператор сверяет журнал по номеру правила и сообщения. Новые известные причины добавляются сюда с тестами.

В Telegram карточки ошибок и журналы используют HTML-оформление: отдельные блоки причины и решения, эмодзи, отступы, нумерованные шаги пересканирования. Общая диагностика ограничивает длину целыми блоками, сохраняя вывод и предупреждения; полный список доступен в «Проблемных доставках». Используется обычный Telegram HTML, без экспериментального RichMessage API для кнопок правил.
