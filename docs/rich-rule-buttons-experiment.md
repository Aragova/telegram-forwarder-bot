# Эксперимент: Rich-кнопки для каталога правил

## Что меняется

В каталоге, поиске, массовом выборе и экране «Добавить существующие правила» название получателя вместе с номером правила находится на кнопке внутри Rich-сообщения Telegram Bot API 10.3.

- Кнопка содержит состояние (🟢 / ⏸), метку 📁 для правил в папке, номер и маршрут «источник → получатель».
- Каждое правило всегда занимает отдельный ряд Rich-кнопок: один маршрут «источник → получатель» на строку, независимо от длины названий.
- 10 правил на страницу. Пагинация и служебные кнопки остаются в обычной inline-клавиатуре внизу.
- Полный маршрут также остаётся доступен в карточке правила.
- Все callback_data перенесены из действующей клавиатуры без изменений.
- Очереди, планировщик, routing, контент и права доступа не меняются.

## Реализация

- [Bot API 10.3](https://core.telegram.org/bots/api-changelog#august-24-2026) поддерживает RichMessageButton и tg-button-row.
- Используется editMessageText с rich_message, а не отправка новых сообщений.
- Адрес локального Bot API берётся из bot.session.api.api_url(). Токен не попадает в логи.
- Rich-экран строится на основе текущего InlineKeyboardMarkup. Оригинальный текст и клавиатура сохранены как fallback.

## Откат без нового PR

По умолчанию: VIMI_RICH_RULE_LIST=admin (эксперимент только для системного владельца, все обычные пользователи видят старый список).
После теста можно включить для всех: VIMI_RICH_RULE_LIST=1.
Чтобы немедленно восстановить прежний интерфейс для всех: VIMI_RICH_RULE_LIST=0 в окружении процесса и перезапустить сервис бота штатным способом.
Схема БД, очереди и настройки не затрагиваются.
Если локальный Bot API не поддерживает Rich-сообщения, бот автоматически вызывает обычное безопасное редактирование. Новое сообщение не создаётся.

## Проверка после развёртывания

1. Открыть общий список из 10 правил. Каждое название должно находиться на Rich-кнопке, без повторного текста.
2. Переключить страницу, открыть правило, вернуться на ту же страницу.
3. Поиск #214, открытие карточки, возврат.
4. Пустая папка → Добавить существующие → выбрать правила на разных страницах → сохранить.
5. Массово убрать правила из папки, проверить доступность в общем списке и отсутствие изменений в очередях.
6. Проверить Telegram Android/iOS/Desktop, включая старые клиенты.
7. Установить VIMI_RICH_RULE_LIST=0, проверить восстановление старого списка.

Примечание: local Bot API должен быть не ниже 10.3. Unit-тесты проверяют форму запросов и fallback; фактическое отображение требует теста с реальным ботом и Telegram-клиентом.
