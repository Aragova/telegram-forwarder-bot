# Менеджер папок правил ViMi Autoposting

## Навигация

- Главное меню → «🔄 Правила» → «📜 Список правил», «🔎 Найти правило», «➕ Добавить правило», «📁 Создать папку».
- «📁 Мои папки» отображается **только при наличии хотя бы одной пользовательской папки**. Системная виртуальная папка «Без папки» физически не создаётся.
- Из папки открывается каталог с полными названиями источника/получателя в **тексте** сообщения, а не в обрезанных Telegram-кнопках. В кнопках только статус и ID.
- В пустой папке доступна **«📥 Добавить существующие правила»**: выбор из всех доступных правил аккаунта, а не из содержимого папки. Можно отметить несколько правил на разных страницах, выбрать всю страницу, затем нажать **«✅ Добавить выбранные (N)»**.
- В заполненной папке **«☑️ Выбрать несколько»** показывает отдельные действия: **«📂 Убрать из папки»** (правила переходят в виртуальную «Без папки») и **«📁 Переместить в другую папку»**. Для одиночного правила «Убрать из папки» есть в дополнительных функциях.
- Карточка правила оформлена как Rich HTML: полный маршрут, состояние, показатели очереди и блок оформления. Кнопки группируются по две с цветами для статусов и действий; все существующие callback-операции сохраняются.
- «⚙️ Дополнительные функции» → «📁 Переместить в папку» позволяет перенести одно правило; массовый выбор доступен в каталоге.
- «⬅️ Назад» возвращает в каталог на прежнюю страницу. Для папок, их настроек, переименования, подтверждения удаления и выбора папки назначения сохраняется контекст страницы.
- «⏪ Откатить» и «🗑 Удалить» открывают отдельные экраны подтверждения. Выполнение возможное только после красной кнопки подтверждения, отмена возвращает в дополнительные функции.
- Администратор входит через активный `handle_admin_reply_keyboard_router` в `bot.py`; альтернативный обработчик меню использует тот же `show_admin_rule_manager`.
- Обычные пользователи используют `user_rules`, а старые постраничные callbacks `user_rules_page` переведены на новую визуализацию.

## Данные

`PostgresRepository.init()` создаёт две таблицы:

1. `rule_folders`: `id`, `tenant_id`, `name`, даты; уникальность названия без учёта регистра в рамках tenant.
2. `rule_folder_assignments`: `rule_id` (уникален), `tenant_id`, `folder_id`; каскадное удаление только **привязки**, не самого правила.

Миграция не меняет поля `routing` или `deliveries`. Существующие правила автоматически считаются находящимися в «Без папки», пока пользователь не переместит их. Удаление папки удаляет только связанные назначения; расписание, обработанные позиции, альбомы, очередь, ошибки, режимы репоста/видео остаются прежними.

`RuleFoldersRepositoryMixin` проверяет `tenant_id` как при чтении папок, так и в массовом перемещении. Для перемещения нескольких правил используется одна транзакция; если хотя бы одно правило не принадлежит аккаунту, перенос не выполняется.
У системного владельца часть старых правил может числиться за системным tenant. В **организационном** каталоге владелец может выбирать такие правила, только если их `routing.created_by` совпадает с его Telegram ID. Их `routing.tenant_id` не изменяется. SQL блокирует перенос чужих правил и перехват уже существующей привязки другого владельца; обычные SaaS-пользователи продолжают работать строго в своём `tenant_id`.

## Поиск

- `#214`: точный ID правила 214, не совпадает с 1214.
- `214`: обычный поиск по номеру и текстовым полям.
- `GROM`, `Light Dante`: поиск без учёта регистра по источнику, получателю или числовым идентификаторам чатов.
- Результаты поиска сохраняют запрос при перелистывании и возвращении из карточки.

## Сессии интерфейса

Состояния поиска, ввода имени, выбора нескольких правил и возврата к экрану хранятся в памяти процесса и сбрасываются при перезапуске бота. Сами папки и назначения хранятся в PostgreSQL, поэтому не теряются при рестарте.

Ввод названия/поиска доступен только в личном чате; при переходе в меню или на другой экран незавершённый ввод отменяется. Для изменения папок предпочтительно менять текущий экран через безопасные обёртки Telegram Bot API.

## Проверка перед выкладкой

1. Убедиться, что GitHub Actions **Smoke Check** и **Python Tests** зелёные для HEAD PR.
2. Применить штатную инициализацию PostgreSQL через `db.init()` (она вызывается при запуске bot runtime).
3. В тестовом аккаунте проверить создание первой папки, её отображение и поиск `#214`.
4. Проверить массовый перенос, удаление/переименование папки и возврат на прежнюю страницу.
5. Проверить новый сценарий создания правила **из папки**, отдельную карточку и два режима «репост/видео».
6. Проверить, что очередь и отправка существующего правила не изменились.

### Откат

Откат кода не требует восстановления `routing` или `deliveries`. Новые таблицы останутся в PostgreSQL как неиспользуемые метаданные. Не удалять их автоматически без отдельной процедуры резервного копирования.
